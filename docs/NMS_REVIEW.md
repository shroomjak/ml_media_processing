# Ревизия NMS, сделанного вручную (`common.hpp`)

Речь про `overlap()` + `select_nms()` — единственный NMS в проекте. Он работает на CPU
и применяется в обоих бэкендах: `decode()` (yolo11) и `postprocess()` (yolo26) вызывают
его по сырым кандидатам, до сборки масок.

## Что происходит по шагам

```
кандидаты со всех трёх сеток (80² + 40² + 20² = 8400 якорей, после порога CONF их десятки)
  -> сортировка по score (убывание)
  -> отсечение до NMS_CANDIDATES = 300 лучших
  -> для каждого кандидата: сравнение со всеми уже оставленными
       если тот же класс и IoU > NMS_IOU (0.45) -> кандидат подавляется
  -> остановка на NMS_MAX = 50 оставленных
  -> make_masks() только для оставшихся
```

Четыре решения в этом коде стоит зафиксировать явно, потому что каждое влияет на результат.

### 1. Подавление внутри класса, а не глобально

```cpp
if (a.cls == b.cls && overlap(a, b) > NMS_IOU)
```

Два объекта разных классов с полностью совпадающими боксами сохраняются оба. Это стандарт
для YOLO: иначе на перекрывающихся объектах («кружка на столе») один класс «съедал» бы
другой. Цена — если модель неуверенно колеблется между двумя классами одного объекта,
в кадре окажутся два бокса. Мультиклассовый NMS (по максимальной оценке без учёта класса)
здесь не нужен.

### 2. IoU считается по боксам, маски в подавлении не участвуют

Маски строятся **после** NMS, поэтому их нечем учесть при подавлении. Так же поступает
Ultralytics: mask-IoU используется только в обучении (в assigner), а не на инференсе.
Практическое следствие: два сильно перекрывающихся объекта одного класса дадут одну
маску — второй объект будет подавлен по боксам, даже если его маска другая.

### 3. Порог 0.45 — самый спорный параметр

В Ultralytics для инференса по умолчанию `iou = 0.7`. При 0.45 всё, что перекрывается
больше чем на 45 %, схлопывается: в толпе людей или на столе с посудой одного класса
объекты пропадают вместе с масками. Значение оставлено 0.45 как в проверенной версии,
но для сегментации разумнее 0.7:

```cpp
constexpr float NMS_IOU = 0.45f; // поднимите до 0.7, если теряются соседние объекты
constexpr float CONF = 0.25f;    // это порог до NMS: сначала он, потом подавление
```

Порядок важен: `CONF` отсекает кандидатов до NMS, `NMS_CANDIDATES` ограничивает список
лучших, а `NMS_IOU` решает, кого из оставшихся считать дублем. Если `CONF` слишком высок,
NMS вообще не доходит до дела — объектов просто нет.

### 4. Ограничение 300 кандидатов и 50 объектов

`NMS_CANDIDATES = 300` — защита от квадратичного перебора: 8400 якорей при `CONF = 0.25`
теоретически могут дать сотни кандидатов, и 8400² сравнений на кадр видео недопустимы.
`NMS_MAX = 50` ограничивает число объектов в кадре (и, соответственно, масок: каждая
160×160 float, то есть 100 КБ). Для сцен с большим числом мелких объектов оба лимита
надо поднимать, помня про память под маски.

## Проверка корректности

- `overlap()` = пересечение / объединение, площади через `max(0, ...)`: отрицательные
  размеры после клиппинга не дают отрицательного IoU.
- `+ 1e-7f` в знаменателе защищает от деления на ноль у двух вырожденных боксов
  (площадь 0 у обоих). Вырожденный бокс при этом получает IoU 0 и никого не подавляет —
  это безопасное поведение, а не шум: клиппинг к 640×640 создаёт такие боксы на краях.
- Сортировка по score до подавления гарантирует, что из пары остаётся более уверенный.
- Порядок «сначала NMS, потом маски» — не оптимизация ради оптимизации: маски
  подавленных объектов не нужны ни для отрисовки, ни для счётчиков, но стоят
  32×160×160 умножений каждая.
- Подавление идёт в координатах letterbox 640×640, до перевода в пиксели исходного кадра
  (`annotate()`). Для IoU это эквивалентно: letterbox — равномерное масштабирование
  с общим сдвигом, отношение площадей не меняется. Пересчёт в исходные координаты
  *до* NMS тоже был бы корректен, но потребовал бы лишних операций на каждого кандидата.

## Чего здесь сознательно нет

- **soft-NMS** (понижение оценки вместо удаления) — для видео без трекинга даёт больше
  ложных срабатываний, чем пользы.
- **NMS по маскам (mask-IoU)** — дорого (попиксельное пересечение масок) и на инференсе
  у Ultralytics не используется.
- **NMS на устройстве** — для голов YOLOv8/YOLO11/YOLO26-seg DFC его не собирает;
  подробнее в `docs/REVIEW.md`.
